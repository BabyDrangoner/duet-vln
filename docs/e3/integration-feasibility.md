# E3 在线完整执行收益学习：集成可行性审查

日期：2026-10-06。范围：只读源码审查、既有结果核对与训练集 probe 的接口复核。没有新增验证集切片或导航，没有修改冻结 E2 代码。本报告替代最初以首跳融合为优先方向的草稿；该方向在本项目中已有不支持继续训练的证据。

## 1. 决策建议

**下一步应先完成训练场景的在线单动作干预机会探测，再决定是否训练收益预测模块。** 核心问题是：在自然轨迹和固定扰动后的轨迹上，改变一次当前动作、随后恢复纯 DUET，能否获得足够多的实际成功率与效率收益。

建议的最小学习模块是：读取当前全局/局部表示、当前指令表示、候选动作和剩余决策预算，预测相对原动作的完整执行 `ΔSR / ΔSPL`，保留原动作作为显式选项。第一版每条轨迹至多干预一次，干预后恢复原 DUET。这使训练分支标签和部署后的继续策略保持一致。多个干预以及显式循环进度状态留到单次干预成立之后。

相对 DUET 提高 5 个百分点 SR、SPL 不下降是研究目标，当前没有可实现该目标的保证。完整 2,349 条任务至少需要 **118 条净新增成功**，还必须控制新增行走距离与误改原成功任务。

### 不重新包装既有首跳融合诊断

已核对 [`route_fusion_result_audit.md`](../../docs/route_fusion_result_audit.md)：

- train_fit 的 1,139 个有效决策中，原策略仅 1 次选择远端动作；train_dev 的 598 个有效决策中仅 6 次。
- 实际首跳替代规则在 fit 不改变动作，在 dev 只改变 1 次且代价更高。
- mean、logsumexp 及 HSPR 对应 2g 规则均没有支持该方案进入训练。
- HSPR 已直接讨论 DUET 的共享回走和，发现这段实现本身不构成新贡献。

这些是既有小规模训练场景诊断，不证明所有路径建模都无效；但足以要求本轮不把“远端候选多”当作充分作用覆盖，也不把简单首跳规则作为优先主方法。E3 probe 应覆盖真正执行的局部移动、全局移动和 STOP，而不是只围绕稀少的远端分支。

## 2. 可直接使用的 DUET 接口

| 接口 | 当前可用内容 | 关键限制 |
|---|---|---|
| `_language_variable` | 当前指令 `txt_ids`、`txt_masks` | 来自 `instr_encoding`；配置截断长度 200 |
| `rollout` 初始语言前向 | `txt_embeds [B,T,768]` | 每条轨迹开始时计算一次；已经放入每步 `nav_inputs` |
| `decision_hook` | `nav_inputs/nav_outs/obs/ended/step/traj` | 在网络输出之后、softmax、STOP 记分和动作选择之前 |
| `gmap_embeds` | 当前时刻经指令交互的 STOP、已访问节点、frontier 表示 | 用 `gmap_vpids` 对齐身份；默认仅 STOP 和未访问节点可选 |
| `vp_embeds` | 当前全景的 STOP、可导航邻居和其他视角表示 | 用 `vp_cand_vpids`、`vp_nav_masks` 对齐；token 总数不能固定成 36 |
| `global_logits/local_logits` | 已分别乘动态融合权重的分数 | 不是未经融合的原始 logits，不应重复乘权 |
| `fused_logits` | dynamic 模式实际使用的动作分数 | 只修改 global/local 字段不会自动重新计算融合 |
| `gmap_masks & ~gmap_visited_masks` | 合法全局动作 | 包含 STOP；已访问节点表示仍存在，但其动作分数是 `-inf` |
| `gmap_pos_fts/pair_dists/step_ids` | 已知图内方向、代价、访问记录 | 不包含可免费读取的未知全景或目标位置 |
| `GraphMap.graph.path` | 实际采用的已发现图路线 | 返回值不含起点，含终点；同点为空列表 |

源码：[`agent.py`](../../third_party/VLN-DUET/map_nav_src/r2r/agent.py)，[`vilmodel.py`](../../third_party/VLN-DUET/map_nav_src/models/vilmodel.py)，[`graph_utils.py`](../../third_party/VLN-DUET/map_nav_src/models/graph_utils.py)。

现有模型没有直接输出“已完成第几个词/子任务”的进度真值。`txt_embeds` 是静态语言编码，当前交互层更新视觉/图节点表示。小型 token attention 或循环记忆可接入，但不能仅凭加入这些结构就宣称学会了真实指令进度。

## 3. 单次在线动作干预的定义

设 `H_t` 为截至当前的已执行历史，`a0` 为原条件下当前真实执行的动作，`a` 为另一个当前合法动作，剩余决策预算为 `15-t`。

对每个候选：

1. 从同一指令起点重放完全相同的 `H_t`；
2. 在 `t` 强制执行且仅执行一次 `a`；
3. 后续全部使用原 DUET argmax，不再增加外源扰动或学习模块干预；
4. 原样执行最终历史终点返回；
5. 对完整实际轨迹 `P(H_t,a)` 计算 `SR`、`SPL`、长度和其他已定义指标。

标签是 `U(P(H_t,a)) - U(P(H_t,a0))`。其中 STOP 对应的是 **立即结束并执行原历史终点 fallback**，不等于停留在当前节点。因此强制 STOP 的效用也必须真正完成返回流程才能取得。

与 E2 的关键区别：在线动作会改变后续观测、未来状态、停止及终点。E2 的结束态候选可以直接在已知返回路径上计算标签；E3 不能用静态距离或 E2 终点 cache 代替分支继续执行。

如果用“当前执行距离 + 到目标的 oracle 最短距离”训练，也可做廉价动作模仿基线，但其标签不是完整执行收益。不能把 oracle 补全的成功当成策略实际完成了导航。

## 4. 当前已对齐的训练-only probe

本轮机会探测的约定：

- 固定 64 条 train_fit、64 条 train_dev；两边使用已有 scene-level 分离，各自运行 natural 与固定 step2 扰动条件。
- natural 只选择 `step0 / step3 / terminal` 中实际存在的状态，去重。
- perturb 只选择 `step3 / step6 / terminal` 中实际存在、位于预定 step2 扰动之后的状态，去重。
- 若轨迹在 step3 前已经结束，记录无 post-perturb 候选；不为它虚构后续状态。
- 没有实际可执行扰动的样本仍保留，并记录 `applied=false`；不能按收益好坏决定保留与否。
- 每个选中状态包含基准动作、少量按原分数确定的合法移动候选和 STOP，按动作身份去重。具体候选排序/并列规则应在实现与冻结配置中完全一致。
- 先做 2 条任务的工程冒烟，再运行固定规模探测；probe 不拟合 head、不访问官方 val_unseen。

扰动条件的候选状态从 step3 起开始，保证 step2 扰动是所有候选共享的已执行前缀。这样干预之后都能恢复纯 DUET。若允许在 perturb 的 step0 干预再重算 step2 扰动，就会改变后续条件策略，不能与本定义混用。

probe 的 oracle 最佳候选只用于训练侧机会描述，是候选集合与状态采样受限的乐观上界，不是可部署策略结果；也不能拿 64 条训练开发样本外推验证集必然提高 5 个百分点。

## 5. 从头重放比克隆活动 agent 更稳妥

`GMapNavAgent.rollout(reset=True)` 会：

- 用 `env.reset()` 回到该指令的起点和朝向；
- 新建 `GraphMap` 和当前轨迹容器；
- 重新计算语言编码；
- 从 step0 开始执行。

可复用同一个已加载模型与环境资源：为每个分支设置 `env.data=[原始指令的拷贝]`，调用 `env.reset_epoch(shuffle=False)`，再直接 `agent.rollout()`。预先设定 `feedback='argmax'`、所有模型 `.eval()`，用 `torch.no_grad()` 执行。

不建议调用不带迭代次数的 `agent.test()`：它会一直执行到遇见重复 instruction ID，单样本情况下会多跑一次。`test(iters=1)` 或直接 rollout 可避免这个额外执行。

每次重放清空 `agent.scanvp_cands`，避免分支遗留状态。环境的静态特征/候选几何缓存可以复用；新的 policy 图和行为历史必须从头生成。保持原环境已加载的图资源和 `gt_trajs` 供结束后评测，不能把它们暴露给干预选择函数。

### 必须检查的重放一致性

- 到目标状态前，每一步的 instruction、viewpoint、候选 ID 顺序、合法 mask、原始 logits 和真实轨迹前缀与参考运行匹配。
- 前缀强制动作使用参考条件实际动作，而非按新排序猜索引；原始分数仍需核验。
- baseline anchor 分支完成后，整条轨迹、终点以及全部评测指标与参考条件一致。
- 候选分支在干预之后可以看到不同状态；不能错误地要求后续继续与参考前缀一致。

重放无需克隆 CUDA 模型、Floyd 图的 defaultdict 内部结构或模拟器对象，代价是每个候选重新计算前缀。这是第一版应接受并计入资源统计的明确成本。

## 6. STOP 与 15 步预算：最容易产生虚假收益的两处

### 6.1 每个强制候选都恢复原始 STOP 证据

hook 之后，DUET 对返回的 logits 做 softmax，并把当前 STOP 概率写入 `graph.node_stop_scores`。强制某动作时，即使只改一个分数，也会改变历史终点证据。若不修正，分支同时改变了当前动作和终点重排序器，标签含义便不再是单动作干预。

正确流程：

1. hook 中先保存当前状态未经强制修改的原 `fused_logits` 和原 STOP softmax 概率；
2. 强制选定候选，仅控制这一次真实动作；
3. 包装 `make_equiv_action`，调用原动作执行后，恢复当前节点原 STOP 概率；
4. 再让原 rollout 运行后面的历史最高 STOP 节点选择与返回。

这对强制移动、强制 STOP、重放的扰动步及 baseline anchor 都必须一致。不能把强制 STOP 概率 1 写入历史表，否则会让 STOP 从“原历史 fallback”变成“无条件留在当前点”。

### 6.2 最后一轮与无可选 frontier 不能强制移动

原 rollout 在以下条件直接把真实动作设为 `None`：原动作选择 STOP、`no_vp_left`、已结束、或 `t == max_action_len-1`。因此零起算 step14 无论 logits 如何都不能再移动。

- step14 或 `no_vp_left` 状态只允许真实可执行的 STOP；不能把未执行的移动候选当成分支结果。
- 每个分支始终保留原总计 15 次决策上限，不能从干预点重新获得 15 次。
- 记录请求动作和实际动作，并核对二者；实际 route 必须结束于请求目标，或明确为强制结束。

## 7. 标签隔离与可执行路径

observation 同时含 `gt_path` 与 `distance`。模型和候选选择器必须使用白名单输入，不读取这两个字段，也不读取环境完整图的最短路距离。

训练分支全部结束后，独立 label/evaluator 才可以访问训练参考路径和完整图：

- 所有候选应先由原分数、合法 mask、固定状态计划选好，不能先看候选收益再扩大搜索。
- 在线输入只含表示、logits、mask、合法动作 ID、指令、已知路线几何和过去执行历史。
- 候选效用、未来分支状态与目标标签单独存储，不能混入特征 batch。
- 当前未观察 frontier 的完整全景特征不能从 HDF5 提前读取；可用的是通过已观察邻居得到的候选表示。
- 测试使用读取 `gt_path/distance` 即抛错的输入；结束前的选择与执行应仍能进行。
- 后续若增加循环状态，必须按 episode 重置且只读取过去到当前状态，不能用双向未来特征。

当前 DUET 使用 `newEpisode` 直接到达全局动作终点，同时把已发现图的完整路线写入轨迹。这是离散 R2R macro-action 方式，不是机器人连续控制。真实性核验应检查每一对连续节点的连接及全部行走长度，包括跨 segment 边、回退和最后历史返回。不能剪去失败前缀、免费回到过去，或用完整环境图中尚未发现的捷径。

## 8. 指令进度、显式回退和再探索的实现难点

### 持续指令状态

小 GRU 或指令 token attention 可以使用当前 hook 提供的表示，不增加骨干前向。但 R2R 没有可靠词到路径节点对齐，空间投影进度只是代理监督。先验证“动作的实际继续收益可预测”，再决定进度状态是否是必要机制。

若只加入 GRU 却没有超过同容量当前状态头、或把路径距离回归改名为语义进度，不足以形成有支持的独立贡献。

### 显式访问旧节点

默认模型已有非局部 frontier 动作，执行时可经过旧节点回退。解析器也有 `act_visited_nodes`，但开启会改变动作集合，并产生重复决策节点。

原 `node_step_ids`、视觉节点嵌入、`node_stop_scores` 会在重访时覆盖；E2 的唯一节点访问假设会失效。若以后开放 visited 动作，需要新的访问事件记忆、循环控制和相同动作空间的 baseline；不能直接复用 E2 的不重访 runtime。

当前 probe 不需要开放 visited 节点，也不需要改变原动作预算，因而适合先判断是否值得继续。

## 9. 公平预算与成本上界

设有 128 条固定指令、两种条件，共 256 个参考 episode；每个最多 3 个状态，每个最多 4 个去重候选。朴素全重放上界约为 **256 个参考 rollout + 3,072 个候选 rollout**。真实数量会因重复状态、early STOP、候选不足和基准复用下降；应记录实际执行次数，而不把理论上界当成实测成本。

每个分支最多执行原 15 次决策。骨干加载一次、顺序执行分支，小模块本身不是主要 GPU 消耗。不能简单把 E2 单次冒烟显存当成 E3 资源结论。先用 2 条任务的真实工程冒烟测量每分支耗时和峰值显存，再估计全 probe 所需时间。

正式方法比较必须保持：

1. 相同骨干 checkpoint、视觉特征、指令截断、图构建及高层决策上限；
2. 完整路径计费，单条实际执行轨迹计分；训练分支搜索不能出现在推理资源之外；
3. 相同训练采集数据和优化预算；报告额外缓存体积、分支次数、GPU 时间、推理时延和显存；
4. 若每轨迹仅允许一次学习干预，所有方法使用相同次数限制；若扩展到多次干预，重新定义训练后续策略与对照；
5. 自然 train_dev 上预先固定 checkpoint 选择；不得用验证集选门槛、挑失败分组或追加候选；
6. 登记后完整验证，报告 SR、SPL、路径长度、误改成功任务和净救回数量，而不只报告 oracle 机会。

## 10. 最小可测学习方案与停止条件

probe 通过工程一致性后，建议比较：

- 原 DUET；
- 相同输入/容量的专家动作模仿或原 logits 残差头；
- 绝对完整执行效用预测，再减去原动作效用；
- 相对完整执行收益预测；
- 仅在前述对比支持后，再加入持续指令状态。

第一版的部署规则应与 probe 定义匹配：原动作作为明确基准，每条轨迹至多改变一次；干预后纯 DUET。仅把效用减去常数基准不会自动产生新的排序优势，因此绝对效用控制仍然必要。

如果固定训练侧候选的成功救回覆盖不足，或机会几乎全部来自扰动而自然开发轨迹没有支持，应降低这条路线的研究优先级。若有 oracle 机会但学习模型无法保留原成功轨迹，问题转为收益预测与分布迁移，不能继续用 oracle 上界替代方法结果。

**当前实现边界**：尚未据本文件实现新的学习模块；只为独立训练-only probe 提供接口与审查约束。最终论文规模和 +5 pp 目标仍取决于后续实际训练、自然开发集结果以及完整公平导航验证。

## 11. 独立工程复核记录

新增独立测试文件 [`test_continuation_probe_integration_audit.py`](../../tests/test_continuation_probe_integration_audit.py)，使用小型已知图驱动模拟原 rollout 的动作与 STOP 记账，9 项测试通过：

- 强制 STOP 后仍使用原始历史证据选择返回终点，并保留已执行前缀及返回段；
- 强制移动后恢复纯 DUET，原 15 次总决策预算不重置；
- step14 / 无 frontier 状态不产生未实际执行的移动分支；
- natural 多个状态的原动作 anchor 完整路径复现；
- perturb 的 step2 只存在于共同前缀，目标状态之后不重新扰动；
- early STOP 不虚构 post-perturb 状态，前缀身份不符立即失败。

测试 observation 读取 GT 字段即抛错，模拟 evaluator 的任何访问也抛错，hook 仍可完成动作记账。这些是工程语义检查，不能替代真实 T4 冒烟、真实连接图检查或导航收益结果。
