# E3 一手文献核验与可行性建议

核验日期：2026-10-06。目标：在本项目冻结的 DUET 上，R2R 导航 SR 增加至少 5 个百分点，同时 SPL 不下降。本文只查论文和官方代码；没有执行或读取新的项目验证集实验。

## 结论

**建议研究“相对原策略完整续跑收益的过程动作干预”，优先做训练集内的可恢复空间与小模型可学习性验证。暂不把 +5 pp 写成可保证的结果。**

在本次核验的直接 DUET 改进中，标准 R2R val-unseen 的模块收益多为 SR +1～3 pp。接近目标的 IDEA 是 +4 pp，但采用在线跨任务适应；超过 +5 的 GOAT、ScaleVLN、Route2Step 各自包含骨干、数据规模或任务协议变化。因此，不能用这些总分差推断一个冻结 DUET 的小插件会获得 +5 pp。下文保留这些区别，而不是相加不同论文的涨点。

文献主表中的 DUET 通常四舍五入为 SR/SPL 72/60；这不是本项目检查点的精确分数。正式目标必须用同一检查点、同一评测器的成对差值。以下所有差值均为百分点，SR/SPL 越大越好。

## 二、进度、恢复和重排序的最近边界

### 1. 显式进度与失败恢复已经是成熟问题

**Route2Step（2026-08 预印本）**把语义进度与局部动作执行分开，并在偏航时维持当前子指令，分别监督状态纠正与动作恢复。R2R-CE 的受控消融为 **48.1/43.3 → 55.3/48.2**，确有 +7.2 SR。但系统是两个 Qwen2.5-VL-3B，使用 4 张 PRO 6000、190K 状态纠正样本及 11.5K 动作纠正样本，任务是单目连续控制，不能作为 DUET +5 的直接证据。[论文 §4.1、表 2](https://arxiv.org/html/2608.03143v1)、[官方代码](https://github.com/BUAA-GAMMA-LAB/Route2Step)

**Sub-Aligner（2025 OpenReview 稿件；本次未确认正式接收状态）**已经做显式子指令定位。其 DUET 消融：单独定位 **72/60 → 72.50/62.74**；加入场景描述为 **74.37/64.05**，并依赖 FGR2R 子指令监督及离线 VLM 描述。简单加“指令进度头”不足以支撑新颖性。[原稿表 3、局限性](https://openreview.net/attachment?id=90AtvsW3Fn&name=pdf)

### 2. 最新工作已经覆盖“偏好 + 门控 + 失败数据”

**VerNav（2026-09-01 预印本）**已有同一上下文的动作偏好排序、熵触发证据生成，以及随后用 rollout 做 step-level RL。采用 Qwen2.5-3B LoRA，在 H100 80GB 训练；其 verifier-only RFT 的 R2R val SR/SPL 为 **39.63/34.13**，不是强 DUET 上的增益证据。[原论文方法、表 3](https://arxiv.org/html/2609.00920v1)

**AVERT-VLN（2026-09-30 预印本）**已有偏航监测、共享决策锚点的纠正偏好训练。主表大幅提升包含**在线人类辅助恢复**；例如 StreamVLN 的 R2R-CE **56.9/51.9 → 63.7/42.6**，SR 涨而 SPL 明显降。自主 RxR-CE 消融为 SR **52.88 → 55.03**，较额外 SFT 高 1.62 pp。监测器全参训练使用 8 张 H20。因此，“从失败构造偏好对”或“按需恢复”都不能单独宣称新。[原论文 §III-E、表 I–II](https://arxiv.org/html/2609.39579v1)

**FeedTTA（ICML 2025）**明确定义测试后接收每回合成功/失败二元反馈。这样的反馈可以改进策略，但与无目标标签的固定模型导航不同；本项目若保留原协议，不能引入这种反馈后继续声称同条件提升。[PMLR 原文入口与摘要](https://proceedings.mlr.press/v267/kim25ad.html)

### 3. 多候选选择必须记执行成本

**Mind the Gap（ACM MM 2023）**在已执行轨迹中重定位终点：DUET R2R val **72/60 → 75/60**，test **69/59 → 71/58**，真实回走没有保证 SPL 不降。论文另报裁剪路径的分数，裁剪不能用于本项目在线完整执行指标；其 SIG_DUET 上 +4 SR 也不能误写成普通 DUET +4。[原论文表 1、§4.3](https://arxiv.org/html/2308.03244v1)

对于从起点执行多条完整轨迹再挑最好的一条，本次未核验到“同一冻结 DUET、计入全部探索/回退成本、低算力、自然 R2R SR +5 且 SPL 不降”的一手证据。不能把 best-of-K 的目标可知上界当成可部署选择器。训练期可克隆模拟器状态做反事实续跑；测试期探索后的动作成本和观察历史必须保留。

## 三、最推荐的一个方向

### 训练期比较完整续跑，推理期执行小型过程纠正器

**研究问题：**当前动作看起来合理，是否仍会在原策略后续执行中失败？在同一已观察历史上换一个合法动作，是否能提高最后的成功率，同时避免消耗过多路径长度？

这是待验证的设计建议，不是文献已经证明的 +5 方法。建议先固定为单次过程干预，以便让训练目标与部署策略一致：

1. **冻结 DUET 与全部输入资产。** 在 train-fit 自然 rollout 的真实前缀上保存完整策略状态，包括已经探索的图、缓存和步数。选点只能依据当前可观测量或固定采样规则；不要只挑 GT 标注的失败点。
2. **同前缀、同后续策略做分支。** 比较原动作与至多两个合法替代动作；每一分支实际执行后，让相同冻结 DUET 自主运行到终止。替代动作集合仅来自该状态的已知候选，后续看见的新区域不能提前进入头的输入。训练标签可以用训练集 GT 算完整 SR、SPL。
3. **学习两个成对增量。** 小头输入 DUET 的跨模态候选特征、历史摘要及可观测路径成本；分别预测相对原动作的 `Δsuccess` 与 `ΔSPL`。保留二者的向量结构，不用一个随意加权的标量掩盖 SR 与 SPL 冲突。原动作明确提供 KEEP 对照。
4. **选择性单次干预。** 在训练集内部的开发集固定门槛；模型预测有成功收益且效率风险可接受时才改动作，之后回到原策略。门槛必须用完整自然导航选定；阈值本身没有保证跨场景 SPL 不降的理论承诺。
5. **小模型和一次执行。** 先缓存冻结特征，训练可控制在百万级参数以内。分支收集是主要费用，可顺序完成、缓存续跑；推理只做原 DUET 加一个小头。12GB/T4 上的实际显存与耗时仍需烟测，不能从“参数少”直接断言适配。

**为什么先限定一次：**若标签都是“修改一个动作后用原策略续跑”，而部署时连续修改很多动作，学到的收益就不对应实际执行策略。第一次正结果后如扩展多次干预，应重新按当前纠正策略收集数据，而不是直接放宽次数。

### 可以成立的小论文贡献，及必须避免的过度表述

| 候选贡献 | 已有工作覆盖什么 | 本方案需要实际证明的差别 |
|---|---|---|
| 相对原策略的过程动作执行收益 | NavQ 学未来价值；NavGRPO 比较多轨迹回报；VerNav/AVERT 已有共享上下文偏好 | 将同一前缀的原动作与替代动作都续跑到结束，以实际完整执行的 SR/SPL 差值监督；验证这种标签比绝对 Q 和专家动作标签更有效 |
| 同时控制成功增益与路径效率的轻量干预 | 门控、进度监控、失败恢复都已有；小参数本身不是算法创新 | 在固定 DUET 输入与单次干预预算下，能识别“失败风险高但纠正无收益”的状态，减少有害修改；实际闭环 SR 提升且 SPL 达标 |

“指令进度”可作为辅助特征或后续消融，暂不作为独立创新点；否则需要与 Route2Step/Sub-Aligner 清楚区分并完成去除进度的受控实验。也不宜把本设计写成首次反事实导航、首次动作偏好学习、首次恢复机制或保证安全的策略改进。

### 论文价值的反方审查

对固定前缀状态 `s` 和原动作 `a₀`，相对标签 `ΔQ(s,a) = Q(s,a) − Q(s,a₀)` 只减去了与候选动作无关的常数，因此不会改变该状态内的动作排序；对成功与 SPL 两个分量都成立。绝对价值模型同样可以通过 `Q̂(s,a) − Q̂(s,a₀)` 实现 KEEP 门槛。直接回归差值可能改变有限数据下的误差相关性、标定或学习效率，但这些是待证明的统计收益，不能把减法本身写成新决策原理。单次干预只是让续跑标签与部署策略一致，并不自动形成研究贡献。

如果资源匹配的绝对 Q 与专家动作纠正对照达到同等效果，当前设计剩下的是一个可复现的低算力过程纠正实现，尚不足以支撑“相对执行收益学习更优”的方法论文。避免重复 E2，需要先证实过程中的替代动作确有覆盖更广的救回机会，再证明模型能在新场景识别这些机会并控制误伤，且增益超过强对照；否则应收缩贡献或调整问题定义，而不是把终点头移到中途后沿用原故事。只有另行证明相同导航质量下的显著数据/计算节省，才能把效率作为独立贡献。

## 四、两个必须有的强对照

除冻结 DUET 外，建议至少保留下面两个训练对照。固定相同前缀、候选动作、rollout 标签预算、输入特征、训练参数量、更新次数、开发集和推理干预次数。

1. **同容量绝对未来价值头。** 使用相同完整续跑数据分别学习绝对成功率与 SPL；推理时显式计算 `Q̂(s,a) − Q̂(s,a₀)`，再使用与相对头相同的门槛/KEEP 规则。它应能看到相同的原动作特征，避免输入信息不对称；差别限于直接拟合绝对值还是差值。它是 NavQ 思路下的资源匹配控制，检验相对目标是否改善实际泛化。应称 NavQ-inspired control，不能冒充完整 NavQ 复现。
2. **同容量专家动作纠正头。** 在同一批策略访问状态上，用训练 GT 的最短路动作或其候选内合法投影做 DAgger 式交叉熵/动作偏好训练；保留相同 DUET 残差与干预门槛。它检验“完整续跑收益”相对普通纠错监督是否有额外价值，而不只是增加了训练样本。

两对照都必须经过同等开发集选择，不能给新方法精调门槛而让对照无门槛强制干预。若最后加入进度模块，还要有模块去除消融；若增加推理时多候选探索，还要与相同探索预算的普通 DUET 搜索比较，并累计全部执行成本。

## 五、如何判断值得为 +5 目标继续投入

先用严格训练集内的开发环境评估三个问题，避免直接用公开 val-unseen 反复试错：

- **动作空间覆盖与正例支持是否足够？** 分别报告自然 train-dev 和各个预定扰动条件中，“单次合法动作分支 + 原策略完整续跑”的 oracle 可恢复数量、净 SR/SPL 空间、被探索的状态/动作覆盖、可救回的唯一指令数与场景数。当前自然 train-dev 基线 SR 约 97.82%，即使全成功也仅余约 2.18 pp，不能用其 oracle 达不到 +5 来否定 val-unseen 上的潜力。扰动 train-dev 的 oracle 仅描述对应扰动分布和已收集候选的可恢复空间；即使超过 +5，也不是 val-unseen 达标证据。稀少正例提示当前数据难以支持收益学习；有限候选下未发现救回动作，也不能外推为所有动作或其他分布都无改善空间。
- **可恢复性是否能从当前观测学出？** 开发集必须保留自然成功状态，统计净救回、误伤和实际路径长度。只在失败样本中训练/验证会高估部署增益。
- **结果是否依赖训练随机性和公开验证集调参？** 达到内部开发标准后才冻结方案，并用有限、登记过的完整导航试验检验。+5 是实测门槛；单 seed、小幅正差或 oracle 最好候选都不能代替该结论。

本次文献核验支持“把训练信号推进到导航过程、评估完整执行后果”这一研究方向；没有找到可以据此承诺冻结 DUET 必涨 5 pp 的先例。若内部开发证明轻量头容量或数据支持不足，合理升级路径是部分策略适配或预训练数据增强，并把增加的训练预算作为论文实验条件明确报告。

## 六、补查：DescRL（ICCV 2025）

**结论：这篇论文支持动作描述辅助训练的小幅收益，无法支持 DUET 接近 +5 SR。** Kondoh、Kanezaki 的 *Embodied Navigation with Auxiliary Task of Action Description Prediction* 表 2 中，80.02/81.00 SR、74.03/76.27 SPL 均属于 **val-seen**。实际结果如下，均为 SR/SPL 百分数：[原论文表 2](https://arxiv.org/html/2510.21809v1#S4.T2)。

| 方法 | R2R val-seen | R2R val-unseen | R2R test-unseen |
|---|---:|---:|---:|
| DUET | 79.73 / 74.78 | 71.65 / 60.44 | 69.76 / 59.39 |
| + Future-DescRL | 80.02 / 74.03 | 71.73 / 60.04 | 未报告 |
| + Past-DescRL | 81.00 / 76.27 | 72.33 / 61.37 | 69.88 / 59.40 |

由表计算，Past-DescRL 的 val-unseen 增量为 **+0.68/+0.93 pp**，test-unseen 为 **+0.12/+0.01 pp**；Future 的 val-unseen 为 **+0.08/−0.40 pp**。ScaleVLN 加 Past 的 val-unseen 仅 **+0.21/−0.19 pp**，不可把 ScaleVLN 的高基线归功于此模块。[原论文表 2](https://arxiv.org/html/2510.21809v1#S4.T2)

**骨干、数据与预算：**VLN 沿用 DUET/ScaleVLN 设置；先用 R2R 10,819 条训练、1,839 条评估数据训练描述生成器，再训练导航与辅助描述预测。VLN 使用 **1 GPU、1 进程、DAgger、3 层辅助解码器、辅助损失权重 0.1**，涉及策略联合训练。主文没有给出 VLN 卡型、显存、训练时长或明确更新数，不能据此承诺 T4/12GB 可复现。未来观察仅用于训练生成器。[原论文 §3.1–3.2、§4.1](https://arxiv.org/html/2510.21809v1#S3.SS2)
