# D3 全规模训练协议草案

日期：2026-10-03。状态：**待 D3b 模拟器一致性与成本试验通过后，再固定数据清单并实施**。本文只制定训练协议，不授权扩大采集、不修改已冻结的 collector/probe，也不访问官方验证集。

## 1. 先明确实验能回答什么

主比较为同一原始路径与指令池上的四臂：C1 自然轨迹 BCE，C2 已知越过目标增强 BCE，C3 配对数据 BCE，M 配对数据加排序损失。C3 与 M 必须使用逐字节相同的缓存、样本顺序、头部初始化和训练步数。这一比较才能回答配对目标是否增加价值。

**不能同时声称四臂的独立自然 rollout 数、真实状态数和训练计算量全部相同。** 自然轨迹通常更短，重复自然轨迹也不会产生新信息。建议精确匹配原始 path/instruction 池、训练组、自然混合权重、头部容量和 optimizer updates；单独公布真实 rollout/状态数量。用掩码 padding 可以匹配小头的计算行数，不能把 padding 或重复采样算成新观察。

E0 的 193/96 条自然轨迹只验证工程。正式 C1 必须重新覆盖本试验完整的原始路径池。本文把它称为 **C1-D3-pool**，不能简称“全部 R2R 训练数据”。如果论文要声称优于充分训练的普通目标分类器，还应报告 **C1-all**：使用所有 train_fit 原始指令的自然轨迹训练普通 BCE。C1-all 的来源预算不同，应单列为更大数据量的强控制，不混入等来源预算的因果比较。

## 2. 实际缓存的信息边界

依据已冻结的 `src/vln_improve/endpoint_pairs.py`，每个完整 pair 有：

- `pair.path_ids/instr_ids/goal_vpids`：两条真实原始任务及两个互斥目标。
- `rollouts[order][slot]`：两种观察顺序 × 两条真实指令，共四次独立前向。
- `features[T,1536]`：**访问当前节点时**，全局和局部跨模态 STOP token 的拼接，FP32、已 detach。
- `states[t]`：当前节点、朝向、真实完整行走前缀、图 IDs/masks，以及去除文本后的输入 SHA。
- `labels.distance_to_goals[T,2]`、`within_success_radius[T,2]`：与策略输入分离的两目标几何标签。

监督本条指令时必须使用 `labels[:, instruction_slot]`。禁止把双列标签压成 `any(goal)`，也不能对同一 feature 轮流贴上两个指令的目标标签。另一条指令的 feature 必须来自它自己的独立语言/导航前向。

缓存没有“看完完整探索历史后，重新评价所有旧节点”的表示。模型在早先节点的 STOP feature 没有看到之后的节点。相同的是两条指令在同一访问时刻的非文本输入；不同访问时刻的历史前缀本来就不同。本文所有损失和结论都遵守这个边界。

## 3. 固定来源池和采集清单

### 3.1 主池

目标规模为 fit 512 pairs、dev 128 pairs，对应 1024/256 个不同原始 path，各取 D3 已固定的一条真实指令。划分仍由 `select_partition` 决定；train_dev 对适配器隔离，但这些场景已被官方基座训练使用。

在扩大采集前，先做一次 **CPU-only C2 几何可构造性检查**：对 D3 已有 primary path-disjoint manifest 的每条路径检查下文的越过目标路线。完整比较池按原 `selection_hash` 排序，取两条路径都能构造 C2 的前 512/128 对。这是预先规定的几何筛选，不使用模型分数、自然失败、视觉困难程度或训练结果。

如果数量不足，就先报告缺口，停止全规模采集；不能采完后删掉 C2 困难组、给失败组偷偷用自然轨迹替代，或只给某一臂换来源。任何缩小规模的决定必须在训练前另记版本。已完成的 D3b pilot 始终保留原始完整组，即使其中部分不进入后续共同池，也不覆盖或删改。

将以下内容固定为一个新 manifest：pair 清单、原始 path/instr IDs、两种 D3 历史、C2 两条历史、每条源注释与图的 SHA、确定性采样规则、预计 rollout 数。相同路径的其他描述不另行加入某个训练臂。原始路径和场景数分别报告，不能用三条同路径描述扩大独立样本量。

### 3.2 每个 pair 的六个训练槽

| 槽位 | C1-D3-pool | C2 | C3 / M |
|---|---|---|---|
| 公共自然槽 2 个 | 原 DUET 对 I_A、I_B 的完整自然轨迹 | 同左，复用完全相同缓存 | 同左，复用完全相同缓存 |
| 增强槽 4 个 | N_A、N_A、N_B、N_B；引用已有自然缓存 | 每条指令：目标结束的参考历史 1 条，越过目标的历史 1 条 | 两历史 × 两指令；现有四次独立前向 |

公共自然数据必须由原基线的动作、在线 STOP 和末尾 fallback 产生；只保存实际作出观察/决策的节点特征，不给未观察的返回中间节点补特征。增强数据是强制执行的训练历史，最终显式 STOP，不冒充自然导航成绩。

C1 的四个增强槽只是逻辑引用。按下文权重展开后，C1 的损失恰好等于两条自然轨迹的普通平均 BCE，不需要重新跑四条相同轨迹。

## 4. C2 的最小且公平实现

C2 是 [Mind the Gap](https://arxiv.org/html/2308.03244) 已知越过目标增强思路的控制，**不是该论文完整模型或全部数据配方的复现**。主比较控制数据机制，四臂仍使用同一个冻结 DUET 和同一个小头。

对每条原始路径 `P=(s,…,g)`、原始指令 I，固定两条历史：

1. **正终点历史**：沿原始参考路径 P 的首次访问节点执行，最后在 g 停止。
2. **越过目标历史**：先走 P，再走一条图上路线到 q；要求 `3 m ≤ d(g,q) ≤ 6 m`、q 不在 P 中，合并后的首次观察节点数 ≤15。两端的等号明确保留：q 恰在 3 m 处按 R2R `<3 m` 定义属于负例。

q 只依赖该指令的原始路径、训练图和固定生成 seed。先按 `SHA256(seed, scan, path_id, q)` 排序，选择第一个满足约束的 q；图最短路径的平局也固定规则。不能看另一条配对指令的目标来选 q，不能按基座错误或小头分数选 q。

参考图路线只用于生成候选顺序；实际行走仍使用已发现图和 `make_equiv_action`，检查目标未访、中间节点均已访，并记录实际前缀。训练标签始终按真实目标 g 的 `<3 m` 区域计算。若目标已在参考路径中提前重复出现，导致“正终点历史”的首次观察序列不以 g 结束，应在 CPU 检查中拒绝该来源，不能重写标签。

这样每条指令有一条最终正例历史和一条最终负例历史。C2 增强槽的末状态正负比为 1:1，与 C3 四次 rollout 一致，避免把“C2 总在目标外结束”做成弱对照。两类数据的中间正例比例、长度及空间范围仍可能不同，必须报告；不能声称这些边际分布已完全匹配。

## 5. 预算表：什么严格相同，什么如实不同

以下按 fit 512 pairs 计算；dev 128 pairs 不参与梯度更新。

| 数量 | C1-D3-pool | C2 | C3 | M |
|---|---:|---:|---:|---:|
| 原始 path / 固定原始指令数 | 1024 | 1024 | 1024 | 1024 |
| 公共自然独立 rollout 数 | 1024 | 1024 | 1024 | 1024 |
| 另采增强 rollout 数 | 0 | 2048 | 2048 | 0，复用 C3 |
| 每轮逻辑训练槽数 | 3072 | 3072 | 3072 | 3072 |
| 每轮 pair 组数 | 512 | 512 | 512 | 512 |
| 每组自然/增强损失权重 | 0.5 /0.5 | 0.5 /0.5 | 0.5 /0.5 | 0.5 /0.5 |
| batch size | 8 个完整组 | 同左 | 同左 | 同左 |
| epochs / optimizer updates | 20 /1280 | 同左 | 同左 | 同左 |

“另采增强 rollout”是实际执行次数，不保证语义或特征从未重复；若 C2 的参考历史与自然基线恰好一致，应额外报告去重数量，不把它当成独立新证据。C3 和 M 绝不分别重新随机采集两套配对数据。

每个槽最多 15 个真实状态。实现可以张量化为 `[8,6,15,1536]`，只对真实状态算 BCE，padding 无标签权重。每 update 最多处理 720 个特征行；固定大小实现可精确匹配头部计算行数。图像/DUET 特征提取成本另记，不因 padding 相同就宣称整体计算量相同。

应同时输出六种计数：独立原始 path、原始指令、实际 rollout、去重的语言条件历史、真实状态、训练中状态被引用次数；再另报 padded 行数、optimizer updates、采集/训练秒数与峰值显存。真实状态多是数据干预的一部分，不能藏在“等预算”三个字里。**C3 对 M 才是严格相同的全部数据与状态预算比较。**

## 6. 损失的精确定义

### 6.1 普通 BCE 和自然混合

每条真实 rollout r 内先对真实状态平均：

`B(r) = mean_t BCEWithLogits(z[r,t], y[r,t])`。

每组 p 的公共自然损失与增强损失分别为：

`N(p) = (B(N_A)+B(N_B))/2`

`A(p) = mean over its four augmentation slots B(r)`

三条 BCE 控制臂都用 `L_BCE(p)=0.5*N(p)+0.5*A(p)`，再对 batch 的八个完整组平均。没有 class weights、hard-example weights、阈值优化或全缓存拟合归一化。较长历史不会仅因为状态更多而获得更大组权重。

C1 中 `A(p)=N(p)`，所以它就是普通自然 BCE。C3 在 BCE 中照样读取完整四格数据，不拆掉困难格、不减少更新数，也不让 M 多看一次自然数据。

### 6.2 M 的配对排序项：访问时前缀，不是未来完整历史

对 pair p、历史顺序 o，令 `t_A`、`t_B` 是两个**原始目标节点**首次被实际观察的索引。它们必须来自缓存 `states[t].viewpoint` 与 `pair.goal_vpids` 的精确匹配，不从 logits 选择“最有利的正例”。

记 `x[o,i,t]` 为指令 i 下访问时刻 t 的 1536 维 STOP feature，`z[o,i,t]=head(x[o,i,t])`。四个分数为：

|  | 访问 v_A 时的前缀 H_o,tA | 访问 v_B 时的前缀 H_o,tB |
|---|---|---|
| I_A | z[o,A,t_A]，正例 | z[o,A,t_B]，负例 |
| I_B | z[o,B,t_A]，负例 | z[o,B,t_B]，正例 |

同一列的两条指令有完全相同的非文本历史；两列的历史长度和位置通常不同。两条顺序同时出现，避免固定“较早节点更好”的排序规则。

`R(p,o) = 0.5 * (softplus(z[o,A,t_B]-z[o,A,t_A]) + softplus(z[o,B,t_A]-z[o,B,t_B]))`

`R(p) = (R(p,A_then_B)+R(p,B_then_A))/2`

`L_M(p) = L_BCE(p) + 0.1*R(p)`。

初版固定 λ=0.1、无温度、无 margin、无类别重权。全部四个目标节点分数来自普通 BCE 已经前向的真实行，不增加未来观测或额外 rollout。这里额外的排序约束就是被检验的训练目标，不能声称“监督约束数量也与 BCE 一样”。

本损失要求每条指令分别偏好自己的目标，但**没有要求**两个原始目标之间的所有指令动作都被正确执行。它也不能证明两个 logit 已经是可跨任务比较的成功概率。新颖性不落在 softplus 公式上。

## 7. 固定模型、三种子与 checkpoint 规则

### 模型与优化

- 全部冻结同一个官方 DUET checkpoint，特征 FP32，原始图像/语言前向处于 eval 模式。
- 直接使用现有 `EndpointProbe` 的 `1536→128→ReLU→1`，不增加注意力、额外记忆或别的模块。
- AdamW：lr=0.001，weight_decay=0.0001；20 epochs；batch 8 个完整 pair 组；无 scheduler、无 mixed precision、无梯度裁剪或自适应 loss 权重。
- 每轮对完整 pair 组洗牌，四格不可跨组拼接。同一 seed 下四臂使用同一组顺序和逐字节相同的初始 head 参数。
- 数据生成、共同来源清单和冻结特征只做一份，三个训练 seed 不重复采集。

### 三种子的含义

预定 head seed 为 0、1、2，只影响头部初始化和训练组顺序。四臂一共 12 次小头训练，不是 12 次 DUET 重新训练。先用 seed 0 检查数据和训练实现；若机制检查不足，可在记录原因后停止后续研究，但不能把单种子结果写成三种子结论。进入正式三种子比较后，不能因某个 seed 表现不好而省略它或改 seed。

### 主 checkpoint：固定终点

**主结果一律用第 20 epoch、1280 updates 的 final checkpoint。** 这是最少选择自由度、也最容易公平实现的方案。train_dev 用于监测和机制判据，不根据各自训练目标选择不同的“最好 epoch”。

在 epoch 5、10、15、20，四臂都在相同的三个 dev 数据面板上记录：完整自然池、C2 增强池、配对池。每个面板独立报告 episode-normalized BCE；配对池另报两条指令同时排序正确率及两种顺序都正确的比例。可以为工程诊断保存 best-dev，但它不能取代主 final checkpoint，不能在看到最终导航结果后切换。

若发生 NaN、缺失数据或来源不一致，整次 seed 标记失败并修复实现；不能用最后一个看似好的早期 checkpoint 掩盖失败。若之后确需 early stopping 或调 λ，先创建新协议版本，四臂共同执行，不修改本版主结果定义。

## 8. train_dev 的共同检查与判据

所有 dev 面板来自同一批原始 dev pair IDs，并与 fit 的场景严格分离。标签不进入 optimizer、归一化估计或采集动作选择。共同监测包括：

1. 每个面板的 BCE、正负标签覆盖、按原始路径/场景汇总的支持量；不能只报总体准确率。
2. 对每种历史顺序，`z[A,t_A]>z[A,t_B]` 且 `z[B,t_B]>z[B,t_A]` 同时成立的比例；相等记失败。另报两种顺序四个不等式全成立的 pair 比例。
3. C3 与 M 的同 pair 差异；C2 与 C3 的同来源差异。相关性按完整 pair 保留，不能把四个 rollout 当四个独立样本。跨场景不确定性按场景聚合，并注明场景数有限。
4. 自然 train_dev 上终点排序的回归检查。它不代表未见场景泛化，不能用其接近饱和的 SR 替代压力集辨别能力。

不通过配对面板就不启动一轮新的验证集搜索。若 M 不优于 C3，拒绝“配对 loss 有贡献”；若 C3 也不优于 C2，当前数据干预没有建立增量。若普通 BCE 已接近配对面板上限，不用更大头或继续改公式强行制造空间。

文本置换诊断必须诚实：现有缓存可以比较同一个真实节点在两条真实指令下的分数是否翻转；如果换输入指令，相应真值也要换列。不能把旧标签配给新指令当成训练样本。缓存也不支持声称做了“移除语言后的基座前向”，除非另行真实重算。

## 9. C1-all 的位置

完整 D3 来源池上的 C1 是主表的等来源控制，E0 不能替代它。为进一步排除“普通目标分类器只是没训练够”的解释，建议在方法值得推进后补 C1-all：对全部 train_fit 原始指令采集自然轨迹，仍以原 path 为上层权重单位，同一路径多描述在其内部平均，防止描述数造成权重偏差。

C1-all 保持同一小头与普通 BCE，每个 update 取 16 个原始 path，读取这些 path 的全部真实描述，先在每条描述内部平均状态 BCE，再在 path 内平均描述，最后平均 16 个 path。路径按 seed 洗牌循环，不能每次独立随机抽样却声称完整覆盖。先在同样 1280 updates 内训练，明确报告实际覆盖的 path/instruction 数；若需更长版本，再单列 updates 和成本。其结果不与 C3/M 伪称严格等数据预算，但如果它已解决问题，就应降低对复杂配对方法的贡献判断。

## 10. 最少实现清单与执行顺序

无需修改已经冻结的 D3b collector、E0 probe/trainer。后续新实现只需要：

1. 一个 CPU 共同来源/C2 路线清单生成器，输出不可变 manifest 和几何筛选计数。
2. 针对完整来源池的自然 feature 采集，以及一个独立的 C2 强制历史采集入口；复用固定 DUET 前向、动作执行和 SHA/Drive 持久化机制，不能复用过小的 E0 数据充数。
3. 扩量版配对采集使用新的配置与输出目录；不能把 pilot 的 32/16 限制直接改掉后覆盖旧身份。
4. 一个只读组装器：读取自然、C2、pair 三种训练缓存，核对共同来源与基座身份；输出完整 pair 组。C3/M 共享组清单，C1 仅使用显式引用，不复制假装独立的数据。
5. 一个组级小头 trainer：复用同架构与持久化基础，增加组级自然混合和配对 loss。保存 optimizer/RNG/组游标，先用合成数据验证断点续跑等价、标签列和四格索引，再跑真实数据。

组装器不能把配对数据硬塞进现有 E0 的 `EndpointCache`：E0 的自然缓存要求 instruction ID 唯一，而同一原始指令在配对/C2 中有多个合法历史。新组级接口应保留 `original_instr_id + context_id/order`，自然标签读取一维向量，配对标签按 slot 取二维矩阵的一列。C2 也需要能区分两个历史的独立缓存格式。共同基座、特征文件、注释、划分与 feature schema 必须一致；不同 collector 的 implementation SHA 则分别验证和保存，不能错误要求它们彼此相同。

本草案的立即下一步仍是完成已授权 D3b pilot，检查严格 parity 与实测成本。上述全规模清单、1280 updates 和后续任何正式导航评估都需固定新配置后执行；本文不追加官方验证访问，也不宣布方法或小论文贡献已经成立。
