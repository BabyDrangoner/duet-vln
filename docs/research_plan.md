## 1. 目标与交付标准

目标是形成可以支撑硕士论文一章及一篇小论文的研究：明确的失败机制、针对机制的方法、可复核的证据，以及完整导航指标的提高。论文规模按独立贡献与实验完整性衡量，不按新增模块数、参数量或代码行数衡量。

原有“困难动作加权 + 残差小头”保留为实验底座和重要对照。仅它超过 DUET，不能认定课题已经完成。

最终至少需要：

1. 确认一种有实际影响、能在固定样本上复核的失败现象。
2. 一个连贯方法，改动记忆表示和学习监督，使动作决策利用这些信息。
3. 同数据、同参数预算的强对照，证明收益来自所提出的机制。
4. R2R 完整实验、3 个训练种子，以及一个第二数据集或第二骨干的迁移实验。
5. 显存、训练成本、完整导航耗时与失败案例。

以上是项目目标；可发表性仍取决于查新和实测结果。

## 2. 拟研究的问题

**研究问题：从不同位置朝一个尚未到达的位置观察时，哪些证据值得用于当前导航决策？后来真正到达时获得的观察，能否帮助模型学会这个判断？**

### 已确认的代码事实

固定 DUET 源码中，`map_nav_src/r2r/agent.py` 的 rollout：

- 在当前位置，把全景平均表征写入当前位置节点。
- 对未访问的相邻候选，把当前位置朝该候选方向的表征写入候选节点。
- `map_nav_src/models/graph_utils.py::GraphMap` 对多次写入累加取平均；到达节点后覆盖为该位置的全景表征。

因此，候选节点的视觉表示可能来自多个源位置，而这些来源在平均后不再单独保留。DUET 每一步仍会重新进行指令交互，不能把问题叙述成“旧的指令分数没有更新”。[官方代码](https://github.com/cshizhe/VLN-DUET/tree/93e8b233164bc079a6db48b8a0a78d123ec8de41/map_nav_src)

默认 `act_visited_nodes=False`，已访节点通常不能再次作为全局动作终点；已知路径上的中间节点不逐点采集新观察。因此，同一来源反复计数不是当前主问题。方向候选特征已经过全景编码，也不能把它等同于未经上下文处理的单张局部图像。

### 待验证的研究假设

某些方向视野包含较多源位置背景，或对目标位置只提供局部信息。来自不同位置的证据压缩为均值，可能丢失当前指令所需的差异，改变候选评分并造成错误选择。**当前没有实验表明这已是 DUET 的主要错误来源。**

例子仅用于解释假设：指令要求进入厨房；一个来源主要看见走廊背景，另一个来源可见门内的厨房线索。两者是否应该等权平均，需要结合指令和几何判断。不同视角也可能提供互补信息，所以不能直接惩罚特征方差。

## 3. 方法设计：一个问题下的两个相互依赖的改动

### A. 保存可追溯的候选证据

为未访问候选保留有界集合：源位置、朝向、相对几何、采集时刻和视觉特征。区分代理观察与已经到达后的实测观察。

- 来源 ID 仅用于关联，不作为可学习的房屋 ID。完全重复记录的处理属于数据完整性检查，不作为方法贡献。
- 使用相对方向与位置，保留不同来源可能提供的互补信息。
- 每候选先限制 4 条来源记录，作为工程起点；正式结果检查容量敏感性。
- 指令条件下的聚合保留各来源差异；集合清空边界为每个 episode。

这部分是监督和决策所需的表示基础。保存来源、使用注意力都不能单独宣称创新。

### B. 用到达后的观察学习校准，再作用于当前决策

训练房屋中，将到达前的证据集合与后来在候选位置实际获得的观察配对。训练一个小模块，预测获得新观察后，原有判断可能怎样变化，并据此聚合证据和修正动作分数。

推理时只输入当前与历史已获得的证据、指令和已发现图。到达后的观察仅用于训练目标；候选的未观测图像不进入推理输入。

**第一版监督必须先做有效性检查：**

1. 固定到达前同一状态的指令、已发现图、位置和动作 mask，只替换某候选的代理视觉为训练期实测视觉，重新计算候选相对其他动作的 logit margin。
2. 这个差值叫“表示替换敏感性”，不叫可靠性真值。它可能包含视野变化或分布外输入造成的变化。
3. 检查它在控制基础分数、候选距离、节点年龄后，是否仍与 oracle 动作代价、错误选择关联。oracle 代价只作训练或事后分析，不能等同于完整指令遵循。
4. 只有诊断支持这种联系，才将其作为辅助监督。使用导航动作损失维持任务目标，辅助预测使用稳健回归；权重由开发集确定。

配对需要有效性掩码：未到达、缺少对应观察或无法核对的内容记为未知，不当作负例。
如果改用局部语义一致性目标，只监督两个视角中可以共同核对的内容，并独立验证匹配质量。

不能直接用门外视图与屋内全景的 L2/余弦距离充当正确性标签。也不能把不确定性一律转成扣分，否则可能抑制必要探索。修正应能正负变化，并由完整导航实验判断价值。

**首选可证伪假设：到达监督能帮助模型利用不同来源中被均值丢失的动作信息，其收益超过同证据注意力和普通未来特征监督。** 候选级分数差值不能直接当作每个来源的可靠性标签，注意力权重也不是真值。当前监督构造仍有风险，尚未冻结为最终算法。若该监督无效，就更换研究假设，不通过继续堆模块维持故事。

## 5. 先诊断，再扩大训练

### 阶段 0：基线与采集协议

已完成 T4 零残差轨迹一致性冒烟，以及 12 个训练房屋、2,890 条指令的完整 `train_dev` 基线：SR **97.820069%**、SPL **96.416810%**，rollout **407.975 秒**，PyTorch 峰值已分配 CUDA 内存 **744,403,968 字节**。这不是进程总显存，也不包含全部准备开销。

**这些房屋和指令属于官方 R2R train，基础检查点按官方配方已经在该训练集学习过。** `train_fit` / `train_dev` 仅隔离本项目新增模块的拟合与开发，不是基础模型未见环境测试。该基线接近饱和，适合检查回归和接口，不能作为泛化选题的唯一依据。来源证据见 [协议审计](protocol_audit_20261003.md)。

本轮在首次官方 `val_unseen` 运行前修订协议：

- `train_fit`：适配模块的参数训练、训练标签与采样开发。
- `train_dev`：适配阶段的保留诊断、回归检查；对基础模型已见。
- 官方 `val_unseen`：有限开发、方案及检查点选择、全部消融和三种子报告。禁止用其标签拟合参数或训练归一化；允许有记录的分析和调参。
- 官方 `test_unseen`：方法冻结后的最终盲评候选。账户、数据及提交可用性尚未确认；提交前审查具体文件、模型和协议，再考虑一次 baseline 与一次 method 提交。

先导预算从最多 **12 个候选变体**起步；每次官方验证运行以及利用已有结果进行新的诊断分析都登记目的、配置/检查点 hash、数据范围、结果和后续决定。它是保守起点，可按诊断透明修订；不是工具已经强制执行的上限。最终三种子和预先冻结的消融另列预算，也逐次登记。所有方法保持输入特征、检查点、动作上限和路径计费一致。

完整官方 `val_unseen` 基线已完成：2,349 条任务，SR **71.5198%**、SPL **60.4098%**、nDTW **67.0205%**；T4 导航推理 392.918 秒，峰值分配显存 745,100,800 字节。报告与首次开发访问记录在 `outputs/study-20261003/`，已备份至 Drive。这是开发基线，不是新方法结果。

### 阶段 1：检验现象

首批约 1,000 个训练房屋决策状态用于检查采集、信号及标签构造，随后在适配阶段保留房屋复核。它们均不能证明基础模型在未见环境有相同故障；推广判断还需要登记后的官方 `val_unseen` 开发诊断。

- 统计单来源、多来源及多来源参与动作竞争的覆盖率，防止选了一个几乎不发生的问题。同源重复仅作日志质量检查。
- 检查代理与实测变化是否能预测动作错误，是否优于仅使用距离、年龄、基础分数的简单预测器。
- 仅自然到达的样本有选择偏差：在训练环境加入合法相邻边的分层采样，分别报告自然采集与补充采集结果。
- 固定状态的完全重复记录测试只验证实现稳健性，不作为自然失败机制的证据。
- 对同一批状态做受控遮蔽或来源错配。此类干预用于机制诊断，正常完整导航仍是主结果。
- 用冻结规则划分困难子集，并人工抽查；不能依据最终方法胜出的样本反向定义子集。

若现象罕见，或证据变化不能提供超出简单几何/分数的预测信息，停止这个候选。

### 首轮诊断记录（2026-10-03）

自然到达配对得到 948 条拟合样本和 511 条适配开发样本。其中仅 2 条、8 条来自未被基线选中的候选；多来源视觉离散度在绝大多数样本上恒定。全候选中多来源占约 32%，但实际被选择的多来源候选仅 11/946、17/503。所有重复来源计数为 0。

在固定线性探针下，加入来源统计后的分类 log loss 相对强 P0 为 +0.00610，95% 场景 bootstrap 区间 [−0.00510, +0.02026]；预测 arrival 量为 +0.01215 [−0.00181, +0.03357]，正值表示更差。真实 arrival 对同样本 shuffled 控制的优势也不确定。teacher 与 execution 的分类标签在本批完全相同，不能算作两次验证。

因此当前没有主方法训练的正向依据，也不能由宽区间证明机制无效。仅做一次事先固定规则的扩展：复用原有历史状态和候选列表，以独立模拟器沿已发现合法路径取得分支终点观测，补齐未选候选；不修改实际基线轨迹、不按 oracle 选样本。它属于额外离线观测，并包含新邻居类型和角度，不能称纯视觉补全。规则见 `configs/branch_extension.json`；自然和分支结果分别报告。

### 分支扩展与停止决定（2026-10-03）

固定的 D1 状态补齐了 2,061 条拟合候选、1,087 条保留候选。所有历史全景、可执行状态导航重放和实际下一步观测对照通过，最大误差为 0；额外观测并未修改基线轨迹。

P1 对 P0 的主 log-loss 差为 +0.000284，95% 房屋 bootstrap 区间 [−0.004627, +0.004821]。P3 对 P0 为 −0.0000963 [−0.0001918, −0.0000154]，但对 P0+P1 为 −0.000380 [−0.004994, +0.004560]；这一很小的条件区间不能独立证明拟议机制。真实到达优于错误目标的对照，主要因为错误对照相对 P0 变差；真实到达相对 P0 仍不确定。辅助 regret MAE 没有给出额外支持。没有把多项未经校正的比较挑选为成功结论。

因此停止当前 arrival-margin 监督方案，不继续改探针或筛样本寻求通过。这不证明所有来源聚合方法无效，也没有产生导航收益。保留全部数据和实现，供可复现的负结果说明。

备用 STOP 的固定训练轨迹分析已完成：193 条拟合任务没有历史观察可救回的失败，96 条保留任务仅有 1 条；简单零训练分数均未提高 SR。接下来按 `configs/stopping_validation_diagnostic.json` 登记一次完整官方验证的只读决策轨迹检查，确认实际失败空间。验证标签只作开发分析，不用于拟合。

### 阶段 2：小规模机制验证

同一训练缓存、相同训练预算做“均值 / 来源集合 × 无 / 有到达监督”的二维实验。比较来源注意力加到达监督与普通注意力，还要比较到达监督在均值和来源集合上的增量；若两者相同，不能归因于来源信息的恢复。补充配对打乱及直接未来特征回归对照。先验证辅助目标，随后做真实完整 rollout。只降低离线 loss 不算通过。

### 阶段 3：小论文完整实验

| 组别 | 内容 | 目的 |
|---|---|---|
| B0 | 原始 DUET | 基线 |
| B1 | 现有普通残差头，均匀动作监督 | 排除单纯增加参数/训练的效果 |
| B2 | 保留来源 + 均匀、最近一次、距离加权聚合 | 排除简单存储或规则就能解决的问题 |
| B3 | 相同证据、近似参数量的普通注意力 + 动作监督 | 最重要的同容量强对照 |
| M | B3 加到达监督及其决策校准 | 主方法 |
| A1 | 相同结构，去掉到达监督 | 测监督的独立作用 |
| A2 | 打乱配对的到达目标，匹配损失尺度 | 测是否只起普通正则作用 |
| A3 | 去掉方向信息或改用均值表示 | 测来源结构是否确有必要 |

B3、M、A1 的具体结构确定后合并重复行，不为增加表格规模重复训练。
所有学习方法获得相同额外采集数据；若多采一轮，普通头也获得相同数据。
进一步加入等训练预算的原有动作头微调，避免用“原始模型完全不训练”作为唯一对手。

相关方法比较优先补充 PRET：核对其公开权重、特征和数据条件，条件允许时复现；
论文引用成绩与同条件复现成绩分别标注。不能只凭超过 2022 年的 DUET 就声称达到当前先进水平。
若相对更强方法没有指标优势，需要如实呈现方法适用范围和实测成本，重新评估投稿定位。

开发报告使用完整 R2R `val_unseen` SR、SPL，同时报告 NE、nDTW、路径长度、校准表现、耗时与显存。方案与检查点选择以 SR 为先、SPL 打破平局，路径效率有明显损害的方案不能仅凭 SR 晋级。正式方法与核心消融使用训练种子 0、1、2；报告每个种子和均值/标准差，配对场景 bootstrap 单独报告，不把它当作种子稳定性的替代。全部标为验证集结果，不伪装成盲测。

最终 `test_unseen` 只评估预先冻结的基线和方法；默认使用预先指定的 seed 0，不能依据 test 成绩挑种子。先核对服务、账户、测试特征与导出代码，再审查具体提交。若测试入口不可用，如实报告有限开发后的验证结果和独立迁移证据，不将已参与选择的 `val_unseen` 改名为测试集。

第二项验证优先为 **R4R 的长路径导航**，用于检验更长历史下的方法表现，按其官方协议报告 nDTW/SDTW 等指标并复现匹配基线。当前包装器仅支持 R2R，R4R 需另行实现和核验。若 R4R 数据/基线条件不成立，可在结果产生前改为第二个图导航骨干，记录理由。只有第二骨干验证通过，才考虑声称跨骨干适用。

R2R 上的小幅稳定改善可成为成果的一部分；如果只超过原始 DUET、不能超过 B3，或者改善 SR 却明显损害路径效率，仍不足以支撑所提出的机制。+1 个百分点只保留为预研投入参考，不是发表标准。

## 6. 算力与实现顺序

常备机器按用户提供的 12GB 显存规划；已完成的云端基线使用 Tesla T4。新结构的资源消耗需独立测量。

- 冻结视觉/语言骨干，复用已有特征；先训练有界证据聚合与校准模块。
- 不把可训练参数锁死在原来的 20 万；需要时扩大到百万级，资源开销由实测决定。
- 缓存冻结表征可降低训练成本；若聚合进入图 Transformer 前端，仍可能需要图模块前向/反向。主干参数冻结不等于没有激活显存。
- 训练标签生成需要额外前向；先控制诊断样本数，再估算整批采集费用。
- 笔记本用于开发、机制验证和小规模训练；租卡集中用于大批采集、重复种子与迁移实验。未经实测不给出卡时或 12GB 必定能跑的保证。
- 冻结主干主要减少训练成本，不据此宣称整个导航系统推理更轻。
