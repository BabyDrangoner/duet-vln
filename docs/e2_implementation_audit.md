# E2 实现审计：从目标分类改为相对原策略的终点纠偏

日期：2026-10-06。本文初次审查使用现有代码与已保存 E1 汇总报告，没有读取新的逐条 `val_unseen`。随后父流程完成了训练集真实 T4 工程冒烟，结果见文末；新增 E2 核心仍是原型，尚未完成正式数据采集和训练。

## 1. 建议与证据边界

建议把下一轮问题固定为：**给定 DUET 已经走完的同一条自然历史，某个历史落点相对 DUET 原落点是否能增加成功率和完整路径效率？** 先保留 DUET 的移动与在线终止，只学习有参照、有成本的终点纠偏。表征使用终止步已经产生的历史节点 token，不需要逐节点再次运行基座。

这不是已经成立的创新结论。可检验的两个增量是：

1. 在同一终止上下文中同时比较候选、原落点和终止证据，是否比各时刻独立 STOP 分类更容易判断“应该改吗”。
2. 针对相对原落点的 SR/SPL 收益训练，是否能减少救回收益被损害及返回成本抵消的问题。

以 DUET 为参照、普通回归、加返回成本或加一个门控都不能各自直接算作新颖性。论文规模需要对照证明上述关系有必要，并通过完整导航、训练种子及迁移验证；先行工作边界另见[本轮审计](e2_prior_art_check.md)。

## 2. 已确定的失败现象与尚待验证的解释

根据[完整 E1 报告](e1_full_navigation_results.md)，M 改变 562 个终点，救回 60 条、损害 63 条；相对 DUET 多返回 1219.327 m。其 SPL 差异分解为救回 +1.216 pp、损害 −1.975 pp、两者都成功 −1.089 pp，合计 −1.848 pp。

这直接说明下一轮必须同时处理损害和效率，不能只把二分类准确率或两节点排序正确率当最终目标。它没有直接证明“缓存表征过时”或“人工配对分布差”是根因。后两种解释需由同数据、同容量的对照验证。

### 2.1 E1 学的对象与部署决定不一致

[build_endpoint_features](../src/vln_improve/endpoint_probe.py) 只拼接当前时刻的 `gmap_embeds[:,0]` 与 `vp_embeds[:,0]`，共 1536 维。它不读取原始 STOP 概率、原选终点、终止时刻的返回距离和已走长度。

[per_group_metrics / group_objective](../src/vln_improve/endpoint_group_objectives.py) 对真实状态的 `<3 m` 标签做 BCE，每条历史先平均，再做自然/增强各半的组平均。M 的附加项只在四个原始目标分数间要求正确排序，权重固定 0.1。

因此：

- 同为成功区域的两个节点标签相同，BCE 无法区分哪个导致更长返回。
- 模型没有明确学习“原落点已经正确，应保留”这个相对决定。
- M 的排序对象是人工历史中的两个任务目标，没有直接优化自然终止时整个候选集合中的最终选择。
- 原训练的基本加权单位是来源 pair；部署的收益单位是完整自然 episode。更换目标时必须明示这个变化。

### 2.2 每次访问的表征看到的历史不同

[EndpointReranker.__call__](../src/vln_improve/endpoint_policy.py) 每访问一个节点便立即计算并保存一个 logit，最终 `make_equiv_action` 把历史 `node_stop_scores` 全部换成这些 logit。早期节点的特征没有看到后面的证据。训练缓存也只存访问时的 STOP 拼接，不能离线把这些向量宣称为“同一个完整终止上下文”。

这并不意味着跨步打分在数学上不可行：监督训练可能学会可比较的分数，原 DUET 也使用跨步 STOP 概率。问题是当前 E1 缺乏终止上下文与相对收益的显式接口，是否有帮助必须实测。

### 2.3 训练来源仍有泛化风险

当前 E1 的共同来源是 512 个 fit pair、128 个 dev pair，不是全部自然训练指令。C1 使用其自然历史，C2/C3/M 另含指定生成历史；自然历史与强制历史的长度、可成功节点比例及行为模式未完全匹配。

官方基座训练已经见过 R2R train 场景，完整 `train_dev` 基线 SR 为 97.8201%。新接口在这些数据上会遇到“多数原落点正确、真正可救回任务少”的问题。先统计自然 fit 的可救回、可损害、双方成功但效率不同、全候选失败等支持量，再固定采集与混合方案。不能因负例不足从验证集挖标签，也不能先用人工压力集成功替代自然导航成功。

## 3. 终止上下文表示已经存在

上游代码给出了低成本实现路径：

- [`agent.py::_nav_gmap_variable`](../third_party/VLN-DUET/map_nav_src/r2r/agent.py) 在 `enc_full_graph=True` 时构造 `[STOP] + visited + unvisited`。
- [`vilmodel.py::forward_navigation_per_step`](../third_party/VLN-DUET/map_nav_src/models/vilmodel.py) 对整张当前图进行跨模态编码，再在 `global_logits` 上屏蔽 visited。被屏蔽的是行动分数；返回的 `gmap_embeds` 仍包含 visited 节点的终止步表示。
- 同一步已有 `gmap_embeds[:,0]`、`vp_embeds[:,0]`，可作为终止上下文。

所以可按 vpid 从最后一次 `nav_outs['gmap_embeds']` 取出实际观察候选，复用现成基座前向。这个表示只是 DUET 当前保存的图记忆在终止步的编码，不能称为重新观察过所有全景或复原完整视频历史。

**候选清单必须来自真实决策观察 ID。** 不能把所有 `gmap_visited_masks=True` 的节点、路过的中间节点或 frontier 自动当成已有 STOP 证据的候选。候选列表与原 `node_stop_scores` 的键集合应一致；所有特征按 vpid 对齐，不能依赖 graph token 的排列顺序。

## 4. 新原型与信息边界

新增文件：[`endpoint_intervention.py`](../src/vln_improve/endpoint_intervention.py)。E1 的 collector、head、trainer、evaluator 未改动。

### 4.1 策略输入

`build_intervention_inputs` 读取：

- 每个实际决策观察节点在终止时的 768 维 global node token。
- 终止时 global/local STOP token 的 1536 维上下文。
- 原始访问时 STOP 概率、访问顺序、原 DUET 稳定最大值终点。
- 在线前缀长度、终止节点到候选的已发现图返回长度。

标量包含候选和原终点的 STOP 概率与访问年龄、`log1p(prefix_length)`、各返回长度除以 `1+prefix_length`、返回长度差的同样归一化，以及终止/原终点标记。归一化完全由当前历史确定，没有对验证数据拟合统计量。

接口返回 `InterventionInputs`；`collate_interventions` 用 mask 补齐批次。目标 ID、距目标距离和参考路径长度均不在策略输入字段中。测试用带访问拦截的字典检查 builder 不读取这些键。

### 4.2 模型与选择

`InterventionHead` 用共享 `768→128` 节点编码器处理候选及原终点，用 `1536→128` 编码终止上下文。比较输入为候选、原终点、二者差、终止上下文和允许标量，经小 MLP 输出两个有界预测：相对原终点的 ΔSR 和 ΔSPL，均以 0–1 指标的差值表示。

默认参数量 **362,370**。最后一层零初始化，训练前所有候选预测为零；原终点在所有参数状态下强制输出精确 `[0,0]`，padding 也为零。

`select_intervention` 只接受预测 `ΔSR≥0 且 ΔSPL>0` 的候选，以预测 ΔSPL 最大者为输出。没有候选或最佳值相同时保留原终点。这个规则约束的是预测值，不保证真实 SR 或 SPL 单调改善；模型的错误仍可能损害基线。

### 4.3 独立监督接口

`build_intervention_targets` 只用于训练标签，独立接收：

- 每个候选的真实距目标距离。
- 不改变在线前缀、再按已发现图实际返回后的完整轨迹长度。
- 原评估器的参考路径长度：**参考路径连续节点之间最短距离的累加**，不能替换成起点到目标的最短距离。

逐候选计算原评估器口径：

`SR_j = 1[distance_j < 3]`

`SPL_j = SR_j * reference_path_length / max(total_length_j, reference_path_length, 0.01)`

再减去原终点两指标，得到 `[ΔSR_j, ΔSPL_j]`。减去自身应精确为零，函数显式验证。标签计算用 FP64，训练损失再转换为模型 dtype。

可观测成本使用执行图坐标；监督指标按官方 connectivity 的评估图长度计算。二者在现有实现中有 float32 坐标和 float64 图的末位差异，接口不要求逐位相等。缓存必须保存实际返回路线与各自来源，避免把全图最短路线偷偷替换成已发现图的执行路线。

### 4.4 目标的最低版本

默认 `intervention_loss` 为两指标的普通 Smooth L1 回归，每个 episode 在真实、非原终点候选上平均，再跨 episode 平均。原终点恒等项和 padding 不冲淡损失；全失败历史的标签全零，仍参与普通回归。

另保留 `risk_weight=0.0` 的可控选项：真实相对收益为负时，惩罚预测为正的值，幅度按真实损失加权。它默认关闭，只作为后续同数据消融的候选，不声称已有提升、校准或统计风险保证。本轮没有调 λ。

## 5. 复用与需要重采的部分

旧自然 control 缓存已有 `states`、前缀、原 STOP 概率、节点位置及标签，`reconstruct_natural` 已能核验已发现图和原 fallback。因此它们可帮助先做训练数据支持量及成本重放检查。

**旧 E1 缓存没有最后一步全体 node token，不能直接训练新表示。** 真实 E2 缓存至少需在自然终止时额外存一次 final node/context token，保存基线选择与所有候选实际返回路线。完全冻结基座，特征 detach 后缓存。不要覆盖旧 identity；新 schema 与 E1 分开。

以 15 个节点为上界，新增候选 token 约 46 KB FP32，加上下文和少量标量仍很小。最终表示无需额外基座前向，模型与 Adam 状态本身远低于 12 GB；实际峰值和采集吞吐仍需真实冒烟确认。E1 运行的 CUDA allocated 峰值约 746 MB，只可作为当前冻结基座推理的参考，不是 E2 整机内存保证。

## 6. 最少能论证机制的对照

不建议立刻把全部组件合成一个最终模型，仅与原 DUET 比一次。至少保留下列关系：

1. 同一 E2 自然缓存上，用访问时 STOP 特征与终止 node/context 特征分别做相同容量、相同收益目标的模型，检查终止证据的增量。
2. 相同终止表示、同一数据和预算，用普通成功分类/排序与相对 SR/SPL 目标比较，检查收益目标是否减少有害返回。
3. 相同完整输入与目标，分别总是选择最大收益和允许保留原终点，检查保留规则的收益及漏救回代价。
4. 不带可选损害惩罚与带惩罚的同数据比较；只有前几项存在可靠价值才值得推进该项，不能靠连续换权重制造结论。

上述是需要固定协议的比较关系，不是已经执行或授权无限次验证的配置列表。需要把候选数量、改变比例、救回/损害、双方成功的效率差、自然和增强来源支持量一并报告。增加表示与训练目标有明确机制，但是否足够支持小论文贡献，要由对照、先行工作差异和实际导航结果共同决定。

### 7.1 后续真实 T4 工程验收

固定 8 条 `train_fit` 指令共 44 个历史候选，观察器保持基线全部轨迹和逐条指标不变；候选标签逐一与上游完整路径评测对齐，零头保持原落点。固定批次训练 20 步，与 Drive 第 10 步从空本地目录恢复后再训 10 步的模型、优化器、loss 和推理完全一致。耗时 54.29 秒，CUDA allocated 峰值 757,082,624 bytes。详情见[真机记录](../outputs/study-20261006-e2/real-smoke-v1/smoke.json)。这仅验收新接口与恢复流程，没有检验正式 E2 方法性能。
