# 备用课题审计：DUET 历史停止位置的可比较评分

日期：2026-10-03。状态：平行候选，未立项，未实现新方法，未连接 GPU。主线仍为到达监督与来源证据诊断。

## 1. 建议

**值得做一次廉价诊断，但目前不建议把它提升为小论文主线。** 代码确实把不同时间的动作 softmax STOP 概率用于历史位置比较；其含义与“这里是否是合适终点”并不相同。不过，独立停止分类、历史终点重排、回退与终止的联合控制已有直接先行工作。

尤其是：

- **Mind the Gap（2023）**已经为历史视点预测独立 sigmoid 目标概率，再选最高分的位置，直接绕开动作 softmax 的分母。[论文 §3.4–3.5](https://arxiv.org/html/2308.03244)
- **Tactical Rewind / FAST（2019）**已经联合讨论回退时机、回退位置、历史目标节点及搜索终止，并比较归一化概率与 logits 的排序行为。[论文 §2、§4.3](https://arxiv.org/html/1903.02547)
- **SkillNav 最新公开版本**明确讨论 DUET 的在线 STOP 与历史最大停止概率回退，并用停止相关数据训练。[论文 Appendix H](https://arxiv.org/html/2508.07642v4)

因此，“独立 STOP 头 + 回退”“可比较的历史评分”“统一在线与事后决策”都不能作为未经限定的新贡献。尚可检验的窄问题是：**动态动作集合造成的评分竞争，是否在正常 DUET 中产生有规模的终点排序错误；明确区分终点可信度与继续收益，是否超出普通目标二分类和历史重排？** 当前没有实验证据支持这两点。

## 2. 已确认的代码行为

固定提交：`93e8b233164bc079a6db48b8a0a78d123ec8de41`。核查文件：[agent.py](https://github.com/cshizhe/VLN-DUET/blob/93e8b233164bc079a6db48b8a0a78d123ec8de41/map_nav_src/r2r/agent.py)、[vilmodel.py](https://github.com/cshizhe/VLN-DUET/blob/93e8b233164bc079a6db48b8a0a78d123ec8de41/map_nav_src/models/vilmodel.py)。

1. 根据 `fusion` 选择 `local_logits`、`global_logits` 或 `fused_logits`，随后计算 `nav_probs = softmax(nav_logits)`。
2. 每个未结束回合把当前位置的 `nav_probs[0]` 保存到 `node_stop_scores[viewpoint]['stop']`。键是位置，而不是时间；若另一个协议允许重访，该键会覆盖旧值。
3. 结束条件包括模型 STOP、无未访节点和动作步数上限。进入 `just_ended` 后，代码遍历整个 `node_stop_scores`，取最大概率的位置；若不是当前位置，就在输出轨迹追加已发现图上的最短返回路。
4. **这一回退选择也发生在主动 STOP 时，不仅发生在超时。** 一些论文的简略叙述与此不同，实验应以固定代码为准。
5. 返回过程在这里是追加轨迹，不重新逐点获得图像、调用策略。计费必须包含这段路，不能把此前走过的路径裁掉。
6. 动态融合中，STOP 的全局、局部分数相加；其他节点按局部邻接或回走项融合，再统一 softmax。于是分母同时受合法候选集合、各候选分数及融合结果影响。

必须区分三件事：**是否结束搜索、选择哪个终点、为到该终点付出多少路程**。上游把前两件事部分共用同一动作分数，但末尾的历史选择另行运行；这为诊断提供了入口，不直接证明现有实现错误。

## 3. 数学现象成立，但“存在系统偏置”还没有成立

设某时刻合法移动数为 `N`，STOP logit 为 `z_s`，移动 logits 为 `z_j`：

\[
p_{stop}=\frac{e^{z_s}}{e^{z_s}+\sum_{j=1}^{N}e^{z_j}},\qquad
\operatorname{logit}(p_{stop})=z_s-\operatorname{LSE}_j(z_j).
\]

因此，保持 STOP 分数不动，仅改变竞争项也能改变停止概率。例如：

| 合成状态 | STOP logit | 移动 logits | STOP 概率 |
|---|---:|---|---:|
| A | 2 | 10 个 0 | 0.424926 |
| B | 1 | 1 个 0 | 0.731059 |
| 无合法移动 | 任意有限值 | 空集合 | 1 |

A 的 STOP 相对每个单独移动的 margin 更高，最终概率却低于 B。若合法动作只剩 STOP，概率必为 1，完全不能说明当前位置符合指令。这是应优先统计的极端情况；本审计没有测量其发生率。

但不能从公式直接推断“不同时间的概率不可比较”或“候选数多一定被错误惩罚”：

- 动作概率本来就表达相对继续选项的偏好。增加真正有价值的移动选项，降低停止概率可能完全合理。
- 候选数与房屋结构、轨迹阶段、已探索程度相关；简单相关性不能证明它导致失败。
- 若模型已学会补偿分母，原概率也可能是可用的终点分数。
- 直接比较原始 STOP logit也不是普遍修复：对一个状态所有 logits 加同一常数不会改变动作概率，却会改变它的原始 STOP logit。状态间公共偏移是另一种混杂。
- 任意删掉候选可能删除真正导航信息。只在 softmax 后处理阶段修改竞争集合的实验，是分数敏感性诊断，不是合法环境干预或实际涨点证据。

一个廉价对照是 `z_s - logmeanexp(z_move)`，等于 STOP 对移动的 log-odds 加 `log N`。它消除对整套相同竞争分布重复计数的依赖，并保持公共平移不变；但不保证正确，也不应被包装为新理论。`N=0` 必须单独处理，不能加一个小常数后假装它表示高目标置信度。

## 5. 一条可证伪假设

> **H-stop：在固定 DUET 轨迹上，动作竞争统计引起的历史终点误排序具有实际规模；学到可比较的终点价值后，以前缀可用信息联合决定停止时机和返回位置，能超过同容量目标二分类与事后重排，并在计入返回路程后改善导航。**

这包含一个现象与一个机制链，不能只验证末端 SR 涨点。若普通独立 sigmoid 已完成全部改善，就把结果记为已有思想的有效工程适配，不能继续靠增加模块维持新故事。

若诊断通过，较完整的方法应区分两个量：

- `q_t(v)`：在当前已见前缀下，历史位置 `v` 是否满足终点条件。它是位置目标判断，不是当前动作 softmax。
- “继续的预期收益”与“返回 `v` 后结束的收益”：两者必须使用同一奖励和路径成本单位。一个目标置信度与任意未校准移动 logit不能直接相减。

共享 `q_t(v)` 可以使当前 STOP 与历史返回使用相同位置判断；决定是否继续还需要单独的成本/继续收益规则。**只把一个头在两个地方各调用一次，不等于研究上的统一决策。** 若继续收益需要学习，可用训练轨迹中固定策略的后续结果作为目标；这只是常规价值学习起点，不能自动宣称新颖。首先应与固定阈值、同容量二分类头加距离惩罚等简单规则比较。

R2R 的训练标签可先用与其评测一致的目标距离阈值；必须承认它只是终点近邻判定，不代表完整指令遵循。不能把同一二分类标签换名为“语义完成度”。

## 6. 便宜诊断：先不训练导航模型

### 6.1 需要的日志

每个正常决策保存：episode/scan、时间、当前位置、结束原因、合法动作 mask、三套 logits、实际采用 logits、有效移动数、当前已发现图、前缀实际路径，以及可缓存的停止相关冻结表征。条件允许时保存融合权重；不能把最终 GT 或未来状态放进策略输入。

GT 距离只用于训练标签和事后分析。数据按训练房屋划分；同条轨迹的多个状态不能随机拆到拟合和验证两侧。先复用已有轨迹记录；缺字段时标明缺失，不能从最终路径臆造当时的候选 mask。

### 6.2 第一张结果表应分解什么

在**同一组基线轨迹**上报告：

1. 不回退、直接停在最后决策点的 SR/SPL。
2. 原始最大历史 STOP 概率回退的 SR/SPL。
3. 回退救回的失败数，以及把原本成功终点改成失败的数量。
4. 历史候选集合中存在成功终点但仍选错的比例。
5. 无合法移动、主动 STOP、动作上限三种结束原因的占比及上述结果。
6. 最后追加的返回距离；被选位置在历史中的时间、候选数和竞争分数分布。

这里的“可选历史节点 oracle”只限 `node_stop_scores` 实际拥有观测的节点。完整轨迹经过但没有重新观察的中间节点，不能默默加入选择集合。标准 OSR 可另外报告，但两者不是同一个可实现上限。

### 6.3 必须比过的廉价分数

都在相同轨迹上重选终点并计入真实返回路：

| 对照 | 用途 |
|---|---|
| 原始 `p_stop` / 最后位置 | 确认回退本身是帮助还是损害 |
| 原始 STOP logit | 检查简单去掉 softmax 是否已解决；承认公共偏移缺点 |
| `z_stop - max(z_move)` | 对最强继续选项的 margin；不考虑其余竞争质量 |
| `z_stop - logmeanexp(z_move)` | 检查候选数量项是否足以解释收益 |
| 仅原概率的单调校准 | 校准对照；严格单调变换不会改变历史 argmax，不能声称它改善终点排序 |
| 竞争统计的小逻辑回归 | 用 count、margin、log-sum-exp、熵、时间等检验简单统计修正 |
| 相同冻结表征的 sigmoid 目标分类头 | 最重要强对照，接近 L2Stop / Mind the Gap 的核心目标 |

额外做两个零训练检查：固定 logits 后仅改变 softmax 竞争集合，观察终点排序敏感性；对每个状态所有 logits 加不同公共常数，确认提出的分数是否产生无根据的排名变化。二者只是数学性质测试，不能代替自然数据效果。

### 6.4 只有这些通过，才做在线验证

先比较“仅改最终选点”和“仅改在线停止”，再比较统一版本；三者必须共用同等数据和表征。在线决策只能用该时间的前缀，不能用完整轨迹 Transformer 的未来视觉得分提前截断路径。

若保持非停止移动策略完全不变，基线轨迹的前缀回放可以便宜评估部分提前停止/返回策略。它不能评估基线已停止后继续探索的结果，也不能评估改变中途回退后出现的新观察。涉及这些变化必须重新真实 rollout。

最终指标至少包含 SR、SPL、NE、实际长度和返回距离，并报告动作数分组的 Brier/NLL 及目标节点排序准确度。ECE 等校准指标改善不等于导航改善；同样，排序变好也不等于概率已校准。

## 7. 反例与停止条件

- **回退选择本来很少改变结果。** 如果收益空间集中于极少超时回合，就难支撑总体稳定改善。停止扩大研究，保留为诊断记录。
- **几何/数量并不是原因。** 如果控制时间、目标距离、竞争质量后，count 不再解释错误，应撤回动作数偏置的叙事。分析中使用 GT 距离不代表推理允许使用。
- **简单校正已经足够。** 若 log-mean-exp 或一个普通目标二分类头与复杂方案同样好，应采用简单工程修正；不能因此认定新机制成立。
- **只是更好的事后视频定位。** 若方法仅用完整轨迹重排且不能改善因果在线控制，应按 Mind the Gap 的近邻改进审视，不称统一决策。
- **SR 与 SPL 明显冲突。** 多走路后更有把握不自动构成更好的导航。真实返回路径必须计费，不能用裁剪路径的 SPL 作主结果。
- **停止目标误当完成进度。** 对要求绕行、经过中间地标的指令，接近终点可能尚未完成指令。若只在 R2R 近邻标签上有效，不能宣称跨任务的指令完成判断。
- **统计不充分。** 如果固定预算内没有足够可选择而选错的独立轨迹，结论应是无法验证，不是问题已被证伪，也不是继续堆模型的理由。

## 8. 最终优先级

**保留为小成本平行诊断，优先级低于当前到达证据线的首轮现象检查。** 它的优势是日志重评分和小头训练便宜，错误分型很清楚；弱点是独立停止、历史重排及联合回退控制均有直接前作。

若固定轨迹上普通二分类就取得全部收益，本候选应结束在工程改进。只有发现跨动作集合的可重复错误、简单强对照不能消除、且前缀在线/返回统一控制产生额外实际收益，才值得重新讨论小论文规模。当前没有这样的证据。

| train_dev | 96 | 599 | 598 / 1 | 95 |

摘要中的 `unscorable_stop` 分别为 19、5，**不等于 19、5 次失败停止**。它只表示精确目标处的 teacher STOP 标签不成立。dev 的一个 ineligible 状态也需要纳入历史最大 STOP 选择，不能丢掉。

完整 `baseline-train-dev` 的 2,890 回合有 63 个最终失败，其中 34 个为 OSR 成功但最终失败。按 D1-dev 的 96 个指令 ID 连接，该基线子集只有 2 个最终失败，其中仅 1 个 OSR 成功但最终失败。OSR 包含移动中未重新观察的中间点，故这 1 个也是宽上限，未必存在可选的历史 STOP 成功节点。D1 摘要的 observer parity 为 null：必须先验证 D1 manifest 轨迹与基线子集一致，才能把上述数值用于该缓存的机会解释。该子集不具备建立小论文泛化结论的事件量；12 个房屋也已被基础 DUET 训练见过。

### 9.3 arrival 扩展失败后的下一个单次诊断

先登记一次 **train-only、CPU、无拟合、无阈值搜索** 的机会分析：保留现有 D1 193/96 回合的全部状态，分别汇总，不根据失败、到达配对或 chosen 候选另筛样本。

1. 校验 collection/episode 哈希、关联、状态顺序、所有 STOP 标签与正常终止条件。重建原始历史 STOP 选择，要求与保存轨迹终点完全一致；核对完整已走路程加返回路程与 rollout 指标。
2. 输出“最后决策点直接停下 / 原始历史概率回退”的成功率、NE、距离，以及回退救回、回退损害、两者均成功、两者均失败的计数。
3. 输出实际观察过的历史节点是否存在 `<3m` 成功位置、原始方法仍选错多少、成功历史位置的最小可执行返回距离。未观察中间节点不加入 oracle 集合。
4. 同一完整轨迹仅在最终选点时分别用 raw STOP logit、最大移动 margin、log-mean-exp margin 重评分，全部计入发现图返回距离。没有移动候选时后两分数不可定义，按方法单列未覆盖回合，不把它替换成无穷大，也不静默删掉最后状态。
5. 按三个结束标志给分组计数，并保存每回合结果和分母。可从缓存构造“继续执行既有基线后缀”的事后结果，但首轮不拟合共享成本目标，不评价基线停止之后的未知继续动作。

脚本预期接口：`python scripts/analyze_stopping.py --diagnostics DIR --split train_fit|train_dev --rollout-report FILE --output FILE`。输出明确标为固定轨迹的终点机会分析，不称在线策略收益。若现象仅有一两个回合，结论应为事件量不足，不训练新头；若简单重评分已覆盖机会，也不能据此包装新的停止机制。若之后需要官方 val 的错误分型，必须另行登记访问，不由本脚本自动扩展范围。

### 9.4 实现状态

已实现 `scripts/analyze_stopping.py` 与独立 CPU 核心 `src/vln_improve/stopping_diagnostics.py`；接口如上，另支持 `--collection` 作为目录参数别名。报告包含逐回合结果、按房屋和可重叠结束标志的汇总、各评分的覆盖分母及相同覆盖集合上的基线，并明确列出 SPL 和继续探索的缺失信息。要求指定原 collection-rollout 报告，不接受身份不符的完整基线报告来代替。

核心测试覆盖回退救回/损害、完整路程不能裁剪、强制结束状态、历史同分时取首次位置、无移动评分缺失、3m 成功半径、哈希/身份/轨迹不一致拒绝。实现完成不等于真实机制成立；当前仅通过合成缓存的 CPU 测试，真实 D1 机会表等待已存缓存与 rollout 明细复制后执行。
